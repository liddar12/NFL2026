# R130: honest curated parlay record

October 15, 2026, America/Chicago. Local implementation on
`build/week6-learning-runtime-20261015`, baseline `32c5bfbe`. Not deployed.

## Contract and method

`scripts/as_offered_record.py` reconstructs a separate cohort from committed
`data/parlays.json` blobs. Game cards use the last commit strictly before their
game's kickoff; Week cards use the last commit before the week's first kickoff.
Every included leg must also resolve to a game whose kickoff follows the commit.
The original blob hash, Git SHA, committer timestamp and cutoff remain inspectable.
An archive's `first_seen_utc`, `frozen_utc` or a generated timestamp cannot establish
this provenance. Git evidence is not proof of Netlify publication or serving.

Moneyline/spread outcomes come from FINAL review scores. Props use the matching
week/game/market/selection ledger outcome; a matching review grade is an explicitly
labeled fallback only when the ledger has no row. The RCA's `no_stat_line` void
convention wins over a retrospective review miss. Conflicting outcomes stay pending.
This convention is not new evidence that a missing stat line proves participation.

The optional `weeks[week].as_offered` block in `review.json` contains coverage,
cards, source evidence and separate Game/Week/all summaries. Original full-contract
wins, reduced-leg successes, pure refunds, losses and pending are distinct. The
headline includes full wins plus reduced successes; its denominator excludes pure
refunds and pending. Leg accuracy counts only hit/miss legs, not void/pending.
Copies are not independent statistical observations; no independent-card confidence
interval or statistical significance is asserted.

Owner exclusions do not retroactively alter the original on-field cohort. Affected
legs retain the exclusion's declared time and first Git commit, and `post_kickoff`
compares the latest known timestamp with that game's kickoff. Unknown timing remains
null. The existing archive settlement and financial accounting are untouched.

## Availability and integration

`build_review.load_inputs` reads history once, caching each blob for all games and
legs in the generation. The pure `build` accepts explicit evidence in fixtures.
Daily/gameday already request full checkout history. Shallow/unreadable/missing
history, conflicting latest snapshots, invalid cutoff evidence or unstarted
decision windows cannot produce a complete headline. Partial recovery is reported
as partial, never extrapolated to a full week. Deleted/latest-wrong-week blobs
cannot silently fall back to an earlier card set.

`app/review.js` renders the new pre-kickoff summary separately from retrospective
settlement. Legacy files explicitly say the pregame cohort is unverified; the old
Week 1 16/18 is not presented as prospective performance. No new route/framework,
database, selection change or probability adjustment is introduced.
